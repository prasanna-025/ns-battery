3. Brand Strategy
Positioning
NS Batteries should be presented as a complete energy partner: generation + conversion + storage + backup + mobility power.
Primary emotional theme: family trust and continuity.
Primary technology theme: clean energy, solar generation and intelligent storage.
Primary commercial theme: one place for solar, batteries, inverters and related power products.
Visual tone: premium, confident, cinematic and modern, but still approachable.
Avoid cluttered marketplace aesthetics and generic solar stock imagery.

5. Three.js Experience Architecture
Signature hero scene
Load a lightweight rooftop/solar scene with a realistic but performance-conscious visual style.
Place the family portrait layer in front of the 3D background so the people remain crisp.
Animate a sun/light source subtly to create depth and time-of-day feeling.
Use energy particles/lines to travel from solar panels to inverter, then battery and load.
Bind camera movement and object transitions to scroll progress.
Transition the hero scene into the Solar Solutions section.
Second 3D scene — Energy Flow
A simple interactive diagram can become a 3D explainer:
☀ SUN  →  SOLAR PANELS  →  INVERTER  →  BATTERY  →  HOME / BUSINESS
Performance safeguards
Lazy-load Three.js and heavy assets.
Use compressed textures and optimized GLB models.
Use lower-quality effects on mobile/low-power devices.
Provide a static/2D fallback if WebGL is unavailable.
Keep 3D isolated from ordinary content components.

Input: monthly bill or energy consumption.
Optional input: location and installation context.
Estimate: system size (kW), approximate panel count, annual generation, indicative savings and payback.
Result CTA: Get Site Assessment / Talk to an Expert.
Store assumptions in a TypeScript configuration file, not a database.
Label results clearly as estimates; final sizing should come from professional site assessment.
10. Enquiry / Lead Flow
Recommended flow:
USER → FORM → /api/leads → VALIDATE → EMAIL + WHATSAPP → SUCCESS
Client-side form validation for fast feedback.
Server-side validation in the Vercel function.
Rate limiting / spam protection.
No sensitive information stored in the browser beyond the submission.
Success state with call/WhatsApp fallback.
Environment variables for API credentials; never expose secrets in frontend code.

13. SEO, Performance & Accessibility
Unique metadata for every page.
Open Graph images for social sharing.
Product/LocalBusiness structured data only for verified information.
Sitemap.xml and robots.txt.
Responsive images using modern formats.
Lazy-load noncritical media and 3D.
Core Web Vitals testing before launch.
Accessible contrast, keyboard navigation, focus states and descriptive alt text.
Location-aware content around Ramanathapuram and the actual service area.
14. Security & Reliability
Keep email/WhatsApp API keys in Vercel environment variables.
Never place private API keys in client-side JavaScript.
Validate and sanitize form submissions on the server.
Add rate limiting / anti-spam controls.
Return generic success/error messages; do not leak server details.
Use HTTPS through Vercel.
Maintain preview deployments for client approval before production.
